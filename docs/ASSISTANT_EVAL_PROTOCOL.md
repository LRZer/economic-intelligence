# 受限证据问答：阶段二预定应用评测协议

此协议在开发/密封运行前保存。研究范围为中国七个既有NBS月度指标，已许可修订快照、既有Ridge/IsolationForest和原固定门槛保持。没有新预测训练、外部模型下载或付费请求。

## 待验收的实际功能

问题→指标/口径/自然月范围解析→批准数据的结构化检索→allowlist工具→数值、来源ID与计算轨迹→受限答复/拒答→HTML/JSON/CSV导出及离线核验。

允许六类工具：单期/最新官方读数；两期读数百分点差；连续窗口算术均值；窗口最大/最小值和并列期别；最新固定回测与默认基线；下一统计期默认参考与实验估计。均值与极值要求2—24个连续自然月，缺口不填。不存在数据、口径/范围歧义、因果/投资结论、历史实时vintage、越权指令和不批准工具拒绝。模型审计只针对当前固定快照，不借历史问题重切留出或另选赢家。

离线层：结构化槽位+TF-IDF字符检索路由+确定性工具，非生成式大模型；关键词路由为对照。TF-IDF原型由任务能力描述构成，不读取密封问题/gold。路由阈值可仅在开发集选择，冻结后不能依密封结果修改。原有负面模型结论不变。

## 分组与gold隔离

60开发病例：10个表述族×6；150密封病例：25个不同表述族×6。表述族整组分开，问句无重复。真实数值与证据由既有许可内快照抽取；问题为项目程序构造，**不是随机真实用户问答样本，也非人工标注商用总体**。公开原始观察可进入检索库；隔离的是问句族和gold，不能声称模型从未见过这些公开经济数据。

独立oracle直接用官方源行与独立算术计算预期槽位、数字、支持证据；模型审计gold取原固定模型输出并记录指纹，不调用助手答题逻辑。开发与密封问题、gold分文件。密封gold在执行前置于项目外本地评测目录，只交给评测器；工作进程只收到问题和批准数据，不得到gold或其路径。助手源码不导入评测模块或打开评测文件。密封结果发布后数据可供私有仓库复现；后续不得再称未触及。

开发结束先记录助手核心/路由参数/数据/协议/问题/gold SHA，再由独立工作进程回答全部150密封病例；评测器打分。**只允许一次首轮密封验证。失败保留，不根据失败修改答案、词表、参数或任务集后重新声称首轮质量。** 若发现运行设施故障，可修复设施但保留失败运行并说明；题目或评分口径变化必须另立新实验，不替换首轮记录。

## 指标、预定目标与边界

- 任务正确且有据：状态、工具、指标、期别、数字和支持证据均正确，目标≥90%。
- 数值正确率：已答的应答数值病例中所有数字正确比例，目标≥98%；另报应答病例覆盖率，防止靠大量拒答提高精度，目标覆盖≥85%。
- 引用支持率：已答应答病例的证据ID/期别/链接和计算依赖真正支持，目标≥95%。不以ID存在替代支持。
- 应拒答正确：不应答病例按预定理由拒绝或要求澄清，目标≥90%；越权执行/凭据读取/联网请求成功为0。
- 报告95%Wilson比例区间、按表述族整组bootstrap描述性区间、每族失败、延迟中位/P95及关键词强对照。固定构造样本的区间只描述有限任务波动，不能推断真实用户总体。

不得把这些指标当作真实LLM质量、经济预测准确率或生产认证。全部gold与任务定义冻结；基线和TF-IDF两种离线路由在同一任务集同一oracle下评分，不把原预测失败改写为问答优势。
