原始请求固定保存于[准备记录](validation/assistant-llm-pilot-preparation.json)。服务请求模型参数为`deepseek-flash`、thinking关闭、stream=false、max_tokens=400、单次尝试无自动重试；保守输入每项≤4096 tokens。接口连接成功和返回结构成功必须分别记录。未来执行者先独立保存服务响应的实际model/usage/status与脱敏请求ID，再交给独立评测器按开发gold核查计划/执行数字/支持证据，保存所有拒绝和失败，不因失败调词后替换首轮记录。

这个12项试点不含足够拒答/注入问题，也来自已查看开发集，只用于连接、计划约束与费用测量；不是LLM质量验收集。若要验证LLM业务质量，应在运行前另立未查看、含拒答/注入/歧义任务的协议与gold，另行批准调用次数及预算；既有150题已公开，不能再称独立新封存评测。报告实际总/成功数、覆盖、数值、引用、失败、真实响应模型、token费用及区间，禁止把离线96%迁移成LLM成绩。
